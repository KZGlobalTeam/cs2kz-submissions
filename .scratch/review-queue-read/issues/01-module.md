## Answer

Implemented in commit `fb6aae5`. `server/services/review-queue/review-queue.ts` exports `createReviewQueueRead(store)` with exactly two methods, `getMinePage(filters, bounds)` and `getQueuePage(filters, bounds)`, each running its list and its count in parallel against one `resolveFilters(filters)` value so the old list/count guard asymmetry is structurally impossible. The queue assembly (mappers array, yes/no tallies keyed by `approvalDecision`, myVote precedence, course count, ISO-serialized `createdAt`/`approvedAt`) is field-for-field today's `ReviewSubmissionRow`; the mine assembly is the projected submission row with ISO timestamps plus `voteCount` (yes+no from `countVotesByDecision`, one aggregate serving both assemblies). `ReviewSubmissionRow` and `OwnSubmissionRow` are `ReturnType`-derived from the assemblies and re-exported. Per-read ordering is fixed as today: the queue orders by `approvedAt` desc when the status filter is `approved` and by `createdAt` desc otherwise; mine always by `createdAt` desc. The endpoint wires the Drizzle store; the specs bind the in-memory fake from issue 02.

One seam extension (signed off by the two-axis review and implemented in this ticket): the queue read carries a viewer identity so `myVote` (the approver's own vote in the review table) is reported on every queue read exactly as today. The resolved seam carried the viewer only inside `unvoted: { userId }`, which made `myVote` structurally null: the bare queue read (default `scope=all` view, Unvoted off) had no viewer, and the Unvoted read excludes exactly the rows the viewer voted on. The queue branch of `ReviewQueueFilters` is now three exclusive forms — `{ unvoted: { userId } }` (required again, per the original issue-02 text), `{ viewerId?: string }` (identity only), and the bare form — and `resolveFilters` lands the Unvoted user on both `unvotedUserId` (predicate) and `viewerId` (identity), so the exclusion and the myVote identity can never name different users; the Drizzle adapter and the fake still build predicates from `unvotedUserId` alone. Issue 03 must pass the authenticated approver as the queue identity (`viewerId: user.id`, with the Unvoted user added via conditional spread, never `unvoted: undefined`). Accepted deviation: the mine row is the store's projected row (no `updatedAt`/port fields — `listSubmissionsPage` projects 7 columns) with ISO timestamps plus `voteCount`; no consumer reads the dropped fields.

Tests: 15 new specs (36 in the review-queue suite) — `resolveFilters` variants including the deterministic mixed-key resolution and the type-level unvoted-requires-user rule, plus both assemblies against the planted fake (owner/status filtering, voteCount, myVote with and without a viewer, unvoted exclusion, tallies, mappers, course counts, ISO dates, per-read ordering, bounds clipping, total === filtered set). Change reviewed along both axes (standards + spec) and re-reviewed after the myVote fix; `pnpm lint` (0 errors), `pnpm typecheck`, `pnpm test` (202 passed), and `pnpm build` all pass.
