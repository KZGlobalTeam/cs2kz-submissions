# 03: Edit my unreviewed submission

**What to build:** A submitter can edit their own pending, vote-free submission end to end: an Edit action beside Delete on eligible rows of My Submissions, opening the existing submission form pre-filled with the current content, saving a full replace of that content, and landing back on My Submissions. A submission that is in review or already decided can never be edited — the edit page redirects away, and a save that races a new vote is rejected with a clear conflict message. The create form's confirmation copy is corrected to the real rule.

**Blocked by:** 01 (shared submission-input schema), 02 (mutability guard, list vote counts, table actions cell)

**Status:** resolved

- [x] An Edit action renders beside Delete on pending, vote-free rows of My Submissions, and never once any vote exists or the submission is decided.
- [x] Opening Edit loads the submission's current content into the submission form: map name, workshop URL, notes, the port section (including an existing authorization image), mappers, and courses with their images.
- [x] Saving replaces the submission's content wholesale — including a changed workshop URL (workshop ID recomputed), added/removed/reordered courses, replaced images, and mapper changes — in one request, preserving the created-at timestamp.
- [x] The edit form validates with exactly the same rules as the create form (the shared schema from ticket 01), including the port-evidence cross-field constraints.
- [x] The create form's confirmation copy states the real rule — editable until approvers start voting — instead of "you won't be able to edit it after submission".
- [x] Opening the edit page for anything not owned, pending, and vote-free redirects away, including a submission that gained a vote after the list rendered.
- [x] Saving an edit that races a new vote fails with a clear conflict message and changes nothing.
- [x] Images replaced during an edit are removed from storage best-effort without failing the save.
- [x] A non-creator receives an opaque 404 from the edit save and never sees the Edit action.

## Answer

Implemented in commit `0b67837`. The PUT endpoint `server/api/submissions/[id].put.ts` consumes the shared `SubmissionInputSchema` from ticket 01, so create and edit cannot drift — including the port cross-field rules. The new service `server/services/submissions/update-submission.ts` does a full replace in one transaction: row rewritten (workshop ID recomputed via `assertWorkshopId`, `created_at` untouched, `updated_at` bumped by the column `$onUpdate`), mappers/courses/course-mappers deleted and reinserted. The mutability guard from ticket 02 is re-checked inside the transaction — non-creator → opaque 404, vote/decision race → 409 “Review has started” with nothing changed. After commit, stale stored images (replaced/removed course images, replaced/removed port-authorization image) are removed best-effort via the existing `deleteStorageObjects`. Read side: `GET /api/submissions/[id]` now returns a server-derived `editable` flag (owner ∧ `canMutateSubmission`), computed from the live vote list before non-approver vote-stripping, so a vote landing after the list rendered still flips it; the edit page (`pages/submissions/[id]/edit.vue`) redirects away with a toast when `editable` is false and otherwise maps the detail payload onto the form state (nulls → empty strings, port image columns → image meta, mapper snapshots → mapper inputs). My Submissions renders the Edit action beside Delete under the same `pending && voteCount === 0` predicate as Delete, and the create form's confirmation copy now reads “You can edit it until approvers start voting.” One structural fix along the way: the detail page moved from `pages/submissions/[id].vue` to `pages/submissions/[id]/index.vue` so the new `[id]/edit.vue` route is a sibling, not a nested child of a parent that renders no `<NuxtPage />` (the nested child would never have rendered). Verified end-to-end with playwright-cli against the dev stack (rows hidden on a voted submission, prefilled port/course/mappers/images, rename save landing back on My Submissions, workshop URL change recomputing `workshop_id` 987654321, replaced image save succeeding, voted-submission PUT → 409 with content unchanged, unknown-id PUT → opaque 404, anonymous PUT → 401, create-form copy). Verification loop green: lint, 46 tests, typecheck, build.
