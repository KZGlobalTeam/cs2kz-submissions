# 06: Releases per game and per-game export

**What to build:** Releases are per-game. A release is created in the current game context and only ever contains approved submissions of its own game — the attachable picker hides the other game's maps and attaching across games is rejected. The release manifest and JSON export are per-game: the CS2 export stays byte-identical to today's external CS2KZ dashboard contract, and the CS:GO export produces a provisional JSON carrying `kzt`/`skz`/`vnl` filter keys, refused when any course lacks all three modes' finalized filters, and still marks the release exported. The image pack is untouched.

**Blocked by:** 01, 02, 04.

**Status:** ready-for-agent

- [x] The release manifest resolves each course's finalized filters per the release's game (two modes for CS2, three for CS:GO).
- [x] The new-release page's approved-submissions picker lists only approved submissions of the release's game; the release detail lists only its own game's submissions.
- [x] Attaching a submission whose game differs from the release's game is rejected with a 400 end-to-end (the predicate from 01 is enforced on the attach path).
- [x] The CS2 release export payload is byte-identical to today's (ADR-0008 contract, `classic`/`vanilla` keys, `notes` placeholders) and its contract tests stay green.
- [x] The CS:GO release export emits the provisional JSON with `kzt`/`skz`/`vnl` filter keys per course, and refuses with a 400 when any course lacks all three modes' finalized filters.
- [x] Exporting a CS:GO release marks the release exported, exactly like CS2.
- [x] The image pack downloads work identically for both games, unchanged.
- [x] The CS:GO payload shape lives in the single shaping adapter (the placeholder contract is contained; swapping in the real KZ-dashboard shape later touches only that adapter).
- [x] Tests at seams D and B: byte-identical CS2 export coverage, the CS:GO placeholder shape and its missing-filters refusal, and the game-aware manifest resolution through the release-contents service seam.

## Comments

Implemented 2026-09-11:

- **Manifest filters keyed per the release's game.** `ReleaseCourse.filters` becomes `ReleaseCourseFilters` (`Partial<Record<CourseMode, ReleaseFinalFilter | null>>`) and the resolution iterates `modesForGame(release.game)` — the row is truth, and the store's `WHERE` already guarantees it equals the requested route game. Each course's finalized filters resolve keyed by exactly its release's game's modes: classic/vanilla for CS2, kzt/skz/vnl for CS:GO, each `null` when that mode has no row, never the other game's modes (a rogue other-game row doesn't key). The presence judgment stays export-side (ADR-0012).
- **Per-game export shaping in the single adapter.** `server/utils/export-release.ts` is now the one place that knows any export shape. `toReleaseExportPayload(contents, game)` dispatches: the CS2 branch (`toCs2ReleaseExportPayload`) is the pre-change body exactly — ADR-0008's `classic`/`vanilla` keys and `notes` placeholders, still validated through `NewMapSchema` — so CS2 stays byte-identical; the CS:GO branch (`toCsgoReleaseExportPayload`) mirrors the CS2 skeleton with `kzt`/`skz`/`vnl` filter keys in vocabulary order and 400s via `csgoCourseFilters` when a course lacks any one of the three modes' finalized filters (the stricter reading of "lacks all three modes'" — the placeholder contract only ever ships complete courses). Review polish: the old gauge-agnostic name `toReleaseExport` is renamed `toCs2NewMapExport` (it was CS2-only by behavior), the two branches share one `finalizedFilterToExport` emitter so the CS2/CS:GO filter objects cannot drift, and the CS:GO shape's types + shaper live entirely in this one adapter — swapping in the real KZ-dashboard contract later touches only this file.
