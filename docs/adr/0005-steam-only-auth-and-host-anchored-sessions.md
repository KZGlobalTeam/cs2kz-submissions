# Steam is the only sign-in provider; sessions are server-held, and the whole auth flow derives from the request host, not fixed configuration

Steam is the single identity provider, via the Steam OpenID protocol hand-rolled in-repo (`server/utils/steam-openid.ts`) after the `openid` npm dependency was dropped — the removal's rationale is no longer recorded (the hand-rolled implementation owns the flow completely; the library may simply have been unnecessary on the Workers runtime). Sessions are server-held opaque tokens stored in the database with a TTL, not JWT- or cookie-embedded state. Sign-in URLs, the OpenID callback redirect, and the post-login redirect all derive from the request's origin, and the session cookie's `Secure` flag derives from the request's protocol (`server/utils/auth-host.ts`); the configured realm/return-URL environment variables exist only as a fallback. This is the direct fix for a production bug: the realm was pinned to the `*.pages.dev` host while users browsed the custom domain, so sessions landed on the wrong host and produced a fresh session row per user per day (commit `d05fc15`, with a regression test in `tests/server/utils/auth-host.spec.ts`).

Consequences accepted: preview deployments work without configuration; any future hard-coded host in an auth URL would reintroduce the original bug.
