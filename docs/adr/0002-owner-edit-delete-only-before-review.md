# The submitting mapper may edit or delete their own submission only while it is pending and unreviewed

Submissions were previously immutable to their creator: the create form promised "you won't be able to edit it after submission", and the only delete path was the lead approver's cleanup endpoint. Mappers now own their submissions until the review starts: the creator may edit or delete a submission while it is `pending` and has zero approver votes; once any approver has voted — the submission is *in review* — the mutability window closes permanently, enforced server-side inside the write transaction (a vote landing mid-edit fails the save with a conflict). Edit buttons are hidden on the submissions table once a row has votes, and the edit page refuses to render for anything but a pending, vote-free submission. Delete is a hard delete (DB cascade) that also removes the submission's uploaded images from storage best-effort after commit. Rejected submissions are terminal: fixing a rejection means creating a new submission, not resubmitting the old one. Alternatives considered: allowing edits on rejected submissions to "fix and resubmit" (rejected as the fix loop is a distinctly larger feature — resubmit state transitions, clearing decision artifacts, re-entering the review pool); warning-on-click UX for voted submissions instead of hiding buttons (hidden buttons chosen so the blocked state is never discoverable by clicking); soft delete/archive (rejected as the downstream tooling only ever reads approved maps, and the release pipeline is unaffected by hard deletes of unreviewed submissions). Consequences accepted: a concurrent save can still race a vote cast in the same instant the save is committed (a small, tolerated window at this scale), and orphaned uploads from before this change are not back-filled. The consolidation into the submission-content module (ADR-0011) narrows the first — replace gains a guarded in-transaction update whose zero-row match rolls back — and stops the second from growing: failed insert/replace writes now compensate their unreferenced uploads best-effort, while the pre-change orphans themselves are still not back-filled.
