# The portal serves two games: a game discriminator on submissions and releases, route-scoped game contexts, per-game modes and rules, and per-game release exports — with the CS:GO export shape provisional

The site began as the CS2KZ community's single-game approval pipeline: submissions for CS2 maps, a two-mode rating vocabulary (classic/CKZ, vanilla/VNL), a port flow, and named releases whose JSON exports to the external CS2KZ dashboard (ADR-0008). The same community needs the identical approval process for CS:GO maps, whose ecosystem differs in settled ways: three rating filters instead of two (kztimer/KZT, simplekz/SKZ, vanilla/VNL); no port concept at all (a CS:GO map is an original that later gets ported to CS2, so the isPort flag, the authorization screenshot, and the porting rules belong to CS2 only); course names constrained to the `Main`/`Bonus 1..N` convention rather than free text; and its own submission rules document. Releases and their exports are per-game concerns as well — a release is a publication act for one game, and the CS:GO export will eventually feed a CS:GO KZ API dashboard whose JSON contract is not yet decided.

Decision: one portal, both games, with the game as a first-class discriminator rather than a badge. Every submission and release row gains a `game` enum (`cs2` | `csgo`); a migration backfills all existing rows to `cs2`. The whole app is scoped to one game at a time: page and API routes carry the game as a URL segment (`/cs2/…`, `/csgo/…`; the API mirrors it), the bare path redirects to `/cs2`, and a single top-bar switcher is the only place the game changes — pages never render game badges because every page is already about one game. The submission and release forms carry no game picker; the context is the picker. Switching game mid-edit navigates away from the editor to the target game's submissions overview, discarding unsaved edits — there is no per-form game state to reset, which is why "you lose the changes" is a navigation consequence, not a reset handler. Server middleware validates the game segment so a game-mismatched page is a server-side rejection, not a client flash.

The per-game differences ride the existing seams rather than new ones. Course modes stay one shared enum grown to five values (`classic`, `vanilla`, `kzt`, `skz`, `vnl`), with each game's allowed set and UI labels (CKZ/VNL vs KZT/SKZ/VNL) defined once in a shared constant; the vote form, lead panel, readonly views, and release manifest iterate the submission's game's set, and the review-write spine rejects any vote or decision filter whose mode is outside the submission's game's set — a CS:GO submission can never carry a classic/vanilla rating. CS:GO course naming is enforced by construction in the form (the first course is `Main`, non-editable; "Add Course" appends `Bonus 1..N`) and mirrored server-side in the shared wire schema, so a direct API write with a free name is a 400. CS:GO submissions reject any port evidence in the shared schema; the CS:GO form omits the port section and the porting rules step; the port-authorization columns stay on the table, always null for CS:GO rows — no destructive migration for a field CS:GO never touches. Submission rules become game-keyed: the CS:GO set is a copy of the CS2 steps minus the porting group, an explicit placeholder until the community drafts its own CS:GO rules; the approver checklist mirrors the submission's game's groups through the existing mechanism, so no porting group ever renders on a CS:GO submission.

Releases are per-game: created in the current context, game fixed thereafter (releases have no content-edit flow), attachability lists filtered by the release's game, and attach validation enforcing game equality — a pure predicate consulted at the endpoint, deliberately not a new module fake (a one-line rule does not justify a harness). The image pack is game-agnostic and unchanged. The JSON export becomes per-game: CS2 stays byte-identical to today, preserving the ADR-0008 contract that the external CS2KZ dashboard pastes in; CS:GO emits a provisional JSON mirroring the CS2 skeleton with `kzt`/`skz`/`vnl` filter keys, refused when any course lacks all three modes' finalized filters, and exporting still marks the release exported. The CS:GO shape lives in exactly one shaping adapter, so the undecided contract swaps in later without touching the rest of the pipeline.

Considered: a per-form game picker on the create page, per the first interview round's "explicit required picker" answer. Rejected after the architecture settled on a single global switcher: a form-level picker would be a second place the game changes, and the round-3 decision — one place to switch, reflected on all pages, no badges anywhere — supersedes it; the context is the picker, and the edit page's "switch exits to overview" behavior falls out of navigation with no residual state. Considered: client-side game state (a composable plus cookie) with flat routes. Rejected: links must carry the game so shared review links and Discord embeds land in the right context, and server-side route validation should reject a game-mismatched page instead of flashing the wrong game client-side. Considered: two separate apps or duplicated flows per game. Rejected outright — that doubles every review surface; the discriminator approach keeps one pipeline with per-game data.

Consequences accepted: mode identity is (game, mode), so the shared `vanilla` value is scoped by the row's game — enforced in code, since a single enum column cannot be two types; growing the vocabulary later for another game stays cheap (one enum value plus one constant entry) but enables only modes validated through the game's set. The CS:GO export carries a placeholder contract until the dashboard API is known — the cost is an acknowledged provisional payload, contained to the one shaping adapter, and the alternative (refusing CS:GO export entirely at launch) was rejected because the community wants a concrete shape to iterate on. Per-game queues mean a reviewer must switch context to see the other game's pending work; a count-hint UI was considered and declined by explicit choice — the switcher is the whole mechanism. Existing rows backfill to `cs2`, the port columns remain always-null on CS:GO rows, and both games keep the same course-image spec, tier scale (the site's own 10-level scale, not the portals' coarser ones), ranked semantics, and the entire review spine — the change is scoping, not divergence.
