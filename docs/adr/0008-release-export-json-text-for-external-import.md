# A release exports as copiable JSON text shaped for the external CS2KZ dashboard's import dialog

Exporting a release produces a JSON payload shown in an in-app modal with a copy button — the artifact is delivered as text the operator pastes elsewhere, not as a file download (a sibling endpoint streams the course-image ZIP as a real attachment download). The payload is validated against the shared `NewMapSchema` (`shared/schemas/cs2kz.ts`), which mirrors the external CS2KZ API's shape: snake_case keys (`workshop_id`, `nub_tier`/`pro_tier`), per-course classic and vanilla filters, `state` forced to `approved`, notes coerced from `null` to `''`, and a build-time refusal for any course missing both modes' final filters. Its consumer is a separate CS2KZ dashboard: the operator pastes the JSON into that dashboard's import dialog, which uploads the maps to the CS2KZ API.

The payload is never persisted: it is always rebuilt from the release's live rows, and the GET that builds it is what records the export timestamp marking the release as exported — a read operation with a state-changing side effect, accepted because what matters is the recording, not the delivery. Consequences accepted: the schema is externally versioned, so changes to the CS2KZ API are the driver for this module; a mismatch surfaces as a 500 carrying the validation message rather than silent corruption.
