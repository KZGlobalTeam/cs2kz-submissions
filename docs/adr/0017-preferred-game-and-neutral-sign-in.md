# Preferred game, a game-neutral sign-in, and the user-card game switch

The sign-in page lived under the game spine (`localhost:11451/cs2` was the login page), the Steam callback hardcoded the post-login landing to CS2 (`/cs2/review` for approvers, `/cs2/submissions` otherwise), and the top-bar switcher was the only place the game changed. We moved sign-in to the bare root — a game-neutral page carrying a "preferred game" picker (CS2 | CS:GO) — made the Steam callback land in the picked game's role page, and relocated the game switch out of the top bar into the signed-in user card, where it also updates the preference so the next sign-in lands where the user last worked (ADR-0016's game spine is otherwise untouched: every page still lives under `/cs2/…` / `/csgo/…`, links still carry the game, and the switch re-scopes the current page exactly as before, edit page exiting to the overview).

The preferred game is stored in a per-browser cookie, not on the `users` row: the cookie survives the Steam OpenID round-trip for the callback's redirect, the logged-out sign-in page can read it back without an unauthenticated endpoint, and the preference is a landing nicety that follows the browser, not a property of the Steam identity. Absent the cookie, the landing defaults to CS2, the portal's default context. The attempted-game preservation the auth middleware used to perform (bounce to the login page of the game you tried) is dropped by design — the preferred game always wins the landing; the deep URL was never restored after login anyway, and the user-card switch fixes the game in one click.

Consequences accepted: the top bar is removed (the switcher was its only content); below `lg` the switch is gone — the sidebar, and now its switcher, is desktop-only, consistent with the rest of the navigation; logged-out visitors see no switcher at all, only the neutral sign-in page with the picker; clearing cookies resets the preference to CS2.

Considered: a `users.preferred_game` column — rejected, it needs a migration, an authenticated write endpoint, and an unauthenticated read so the sign-in page could prefill, all to make a landing preference follow the Steam persona across devices. A `/login` page — rejected; the bare root is the more natural "the URL has no game" and removes the `/` → `/cs2` redirect. A returnTo query param on sign-in — rejected; it reintroduces game state into the login URL the feature exists to remove.
