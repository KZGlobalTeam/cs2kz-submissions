# All images live in one public Supabase bucket; protection is at the API layer, not the object store

Course images, port proofs, and rejection attachments all live in a single public Supabase storage bucket under key prefixes (`course-images/`, `port-images/`, `rejection-attachments/`) with plain public URLs; there are no signed URLs and no object-level access rules anywhere. ADR-0001 documents this choice for rejection attachments specifically; this ADR records that it extends to every image in the system. A public bucket means anyone holding a URL can open the object with no authentication — unguessable random-UUID keys are the only accidental barrier. Everything that must stay private is instead controlled at the API layer: vote rows and their attachments are stripped server-side for the submitter, and only the lead's rejection attachments are revealed once a decision lands.

Rejected alternative: a private bucket with signed URLs — it would require new environment configuration, new Supabase setup, and per-render URL signing across the read path, for a small trusted team where zero-config storage consistently matched every other image in the system. Consequences accepted: anyone with a URL can open an image (end-user protection is deliberately at the API layer), and abandoned or orphaned staged uploads may leave objects in storage.
